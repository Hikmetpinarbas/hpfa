## Purpose

The Metric Fusion Engine aligns admitted metric/model candidates, source surfaces, context and construct-specific observation contracts into evidence relations.

It is not a report generator, not a tactical-truth engine and not a product-wide admission gate.

Canonical doctrine:

```text
EVENT ⊂ ZFGV
ZFGV != EVENT
```

ACTION/EVENT evidence is one possible input family. Aggregate/tabular, relational, process, context, spatial and tracking/video-backed constructs must not be rejected merely because they are not event-shaped.

## Product meaning

This module is an evidence-relation scaffold.

A single metric or model output must not jump directly into a football argument. It must first be evaluated against its own construct requirements, supporting/contradicting evidence, dependency/independence lineage and claim ceiling.

## Required upstream authority

Required inputs are construct-specific. A candidate may require, depending on its contract:

- observation capability admission
- metric/construct definition admission
- provenance and dependency lineage
- context evidence
- ACTION/EVENT quality/sequence outputs only when the construct actually requires ACTION/EVENT evidence
- aggregate/tabular support when admitted
- spatial semantics when admitted
- tracking/video authority when physical/off-ball truth requires it

A global Event-Only or event-surface allowlist must never authorize or veto ZFGV product admission.
