# HPFA Positive-Scope Narrative Policy V1

## Purpose

HPFA communicates football knowledge directly, clearly and professionally.

Project language starts from the strongest defensible football construct and states its observed scope in affirmative terms. Governance protects scope through construct definitions, authority roles, admission contracts, claim scope and withdrawal logic.

The default project language is football analysis, not defensive qualification.

## Canonical Rule

For every human-readable HPFA surface:

QUESTION → OBSERVATION → CONSTRUCT → FINDING → EVIDENCE → PROCESS → CONTEXT → CONSEQUENCE → VARIATION → ANALYST VALUE

Use the correct bounded construct name from the start.

Examples:
- Visible Intervention Response
- Post-Loss Transition Protection
- Observed Territorial Access
- Role/Zone Participation Variation
- Visible Transition Tempo
- GK Distribution Consequence
- Process Fate

## Positive-Scope Language

Preferred formulation:
- state the construct name;
- state the observed match-local evidence;
- state the process/context/consequence;
- state the analyst value;
- carry scope through authority metadata and construct definition.

Defensive-negation templates and repetitive caveat blocks are outside current HPFA prose.

## Scope Protection

Scope is carried by:
- construct_id
- construct_definition
- observation_family
- source_role
- admission_state
- dependency_state
- claim_scope
- uncertainty_state
- withdrawal_condition
- authority_role

Human-readable reports should state the admitted scope directly.

## Authority Vocabulary

Use affirmative authority definitions.

Examples:
- Row authority: source-surface observation unit.
- Occurrence authority: admitted match-local action occurrence candidate.
- Aggregate authority: contextual/tabular evidence.
- Coordinate authority: admitted event-location observation.
- Process-label authority: provider/source process annotation.
- Recurrence authority: repeated admitted pattern within the declared scope.
- Model-output authority: model-derived signal within its declared model contract.
- LLM-output authority: analyst communication and synthesis surface.
- Absence authority: unresolved/empty observation state under the declared observation window.

## Analyst Output Rule

Normal analyst-facing outputs contain:
1. Finding
2. Evidence
3. Process/mechanism
4. Context
5. Consequence
6. Recurrence/variation
7. Analyst value

Technical governance fields belong in machine/audit surfaces.

A technical qualification appears in analyst prose only when the qualification changes the football meaning of the sentence.

## Visual Rule

Visuals use the correct construct title and eligible visual grammar. Scope protection is encoded in the representation contract, provenance and construct label rather than repetitive disclaimer text.

## Research Rule

Research originating from richer observation environments is decomposed into:
FOOTBALL QUESTION → REQUIRED OBSERVATION CAPABILITY → AVAILABLE ENRICHED SURFACES → HPFA-NATIVE CONSTRUCT → ANALYST VALUE.

Research is evaluated for transferable football information before disposition.

## Regression Rule

Generated analyst-facing prose must pass a narrative-language regression test. The test rejects recurring defensive-negation templates and requires positive-scope wording.

## Authority

This policy is current project language authority for:
- analyst reports
- user-facing reports
- current governance/handoff prose
- visual labels/descriptions
- research summaries
- donor adaptation notes
- product documentation intended for operators or analysts

Historical immutable records may remain as provenance, while current authority and generated outputs follow this policy.
